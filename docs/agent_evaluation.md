## 2. 指标定义

| 指标 | 定义 |
| --- | --- |
| 工具选择精确率 | 实际执行的工具中属于“必需 ∪ 允许”的比例（额外工具才算多余） |
| 工具选择召回率 | 必需工具被实际执行的比例 |
| 工具选择完全匹配 | 精确率与召回率同时为 1 |
| 工具调用成功率 | `status ∈ {ok, empty}` 的调用 / 全部调用（空结果是合法结果，不算失败） |
| 数值回答正确率 | 数值检查通过数 / 数值检查总数（回答文本中出现与期望值差值 ≤ tolerance 的数值） |
| 证据引用正确率 | ①页面级需求满足率：期望 `doc_key` + 页码区间被引用；②逐字率：被引用 Chunk 的 `quote` 必须逐字出现在该 Chunk 原文（数据库核对） |
| 无依据结论比例 | 出现“已确认故障/确诊/必然是…”等确诊式措辞，或回答数值接地违规的题目占比 |
| 平均工具调用次数 / 平均耗时 | 每题实际工具调用数与端到端耗时 |

**重要**：页面级引用指标是代理指标，不判断“该片段是否在语义上足以支持结论”；
`quote` 逐字率只证明摘录真实存在于 Chunk 中。语义充分性需要人工复核（见 §7）。

## 5. 规划器对比：规则 vs LLM（同一 9 题子集）

| 规划器 | 工具完全匹配 | 状态匹配 | 平均工具数 | 平均耗时 | 主要问题 |
| --- | ---: | ---: | ---: | ---: | --- |
| `rule`（默认） | **1.000** | 1.000 | 2.22 | 4.24 s | 无（该子集内） |
| `llm`（`qwen2.5:7b-instruct`） | **0.778** | 0.778 | 1.11 | 6.01 s | C01 选了 `get_sensor_history` 而漏掉统计/质量/知识检索；H01 漏掉统计工具 → 两题都退化为“证据不足” |

结论：在本项目的中文工业问题上，7B 模型的工具规划不如确定性规则可靠，且每次多花约 1.8 s；
因此默认 `AGENT_PLANNER=rule`，LLM 规划器保留为对比实验与后续模型升级的接口。
这与阶段 2“单一 7B 模型推理能力有限”的结论一致。

## 6. 失败与修复记录

### 6.1 开发过程中发现并修复的实现缺陷

| 缺陷 | 表现 | 修复 |
| --- | --- | --- |
| 条件边清空待执行队列 | 计划 4 个工具只执行了第 1 个 | `check` 节点保留 `pending`（不再返回空列表） |
| 知识问题被误判为数据问题 | “DV pressure 读数为零代表什么”被要求补时间窗 | 去掉“读数/记录/范围/多少/几”等过于宽泛的触发词；只有测点、没有时间不再视为数据问题 |
| 领域名词当成知识意图 | “储气罐压力平均值是多少”被判为混合分析并检索知识库 | 从知识信号中移除 `储气/卸荷/油位/干燥/润滑` 等领域名词 |
| 设备档案问题被判为需要时间窗 | “观测时间范围是什么”被要求补日期 | 移除“范围”这一泛词，设备档案问题不再计划统计工具 |
| 知识问题缺少时间窗仍报错 | 纯知识问题 `needs_time_window=True` | 知识意图强制 `needs_time_window=False` |
| 百分比换算被判成编造 | 模型把 `0.6948` 写成 `69.48%` | 事实文本同时给出小数与百分比；证据文本中的数字全部登记为可引用 |
| 时间戳分量被判成编造 | 模型写“14:30”被判违规 | 证据文本数字登记改为宽松分词（含 `T`/`:` 后的分量）；违规检测仍用严格分词 |
| 引用问题中的日期被判成编造 | 模型写“5月3日”被判违规 | 用户问题中出现的数字计入允许集合 |
| 否定句被判成确诊 | 事实文本“不会被自动视为已确认故障样本”触发确诊规则 | 确诊检查只看模型叙述（结论/推断/知识要点），不看事实清单 |
| 负号数值匹配失败 | `-0.0223` 被识别成 `0.0223` | 数值正则支持前导负号 |

以上缺陷修复后，开发集从“工具完全匹配 0.51 / 状态匹配 0.86 / 数值 0.87”提升到当前结果。
**这些提升来自缺陷修复，而不是放宽期望值**；对期望值的改动见下表。

## 7. 方法学限制

1. **开发集是在规则迭代过程中建立的**（不是预先固定的留出集），因此开发集指标偏乐观。
   为此补做了 11 题留出集，并在本文中如实记录其失败案例。
2. 页面级引用指标不等于“语义充分”；`quote` 逐字率只证明摘录真实存在。
   本阶段**未**做人工语义复核（阶段 2 做过一次，引用完全正确率 69.2%），
   因此不能声称 Agent 的引用语义正确率优于阶段 2。
3. “无依据结论”由措辞规则 + 数值接地自动识别，不能替代人工判断；
   措辞规则存在漏报（例如把推断写成陈述句但不用“确诊”一类词）。
4. 数值检查是容差匹配，未覆盖“数值正确但口径/单位错误”的情况。
5. 故障注入只覆盖三类（知识库不可达、工具超时、预算不足），未覆盖网络抖动、
   连接池耗尽、Ollama 模型被卸载等环境级故障。
6. 未做并发/压力测试；耗时数字是单请求串行执行的结果（本机 Ollama，非生产部署）。
7. 期望值由同一套 Service 计算，若 Service 本身存在口径缺陷，评估无法发现
   （口径缺陷由阶段 1B/1C 的测试覆盖）。
